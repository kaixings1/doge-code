# 双模式架构规划（远端 / 本地）

> 日期：2026-10-08
> 起因：希望 Android 客户端支持两种工作模式 —— **远端**（现有桥接）与
> **本地**（手机自身就是 agent，不依赖电脑）。

---

## 零、先说结论（基于实测数据，不是推测）

| 设想 | 核实结果 | 依据 |
|---|---|---|
| 手机上装 TypeScript 编译 doge-code | **不可行** | 3283 文件 / 77 万行 / 109 依赖 |
| 把 doge-code 打包成 APK（套壳） | **不可行** | 构建产物是 **Windows x64**；Android 是 Linux ARM64 + Bionic，架构与 libc 均不同 |
| 抄一个高星手机编程 App | **没有可抄的** | 见下表：现有方案没有「完整的本地编程 agent」 |
| 新实现一个精简本地 agent | **可行** | 本仓已有可复用的 API 层与配置体系 |

**核心结论：本地模式是一个新实现（约 5k 行），不是 doge-code 的移植。**

## 一、竞品格局（附可信度标注）

> 说明：撰写时**本机无外网**（实测 `github.com` 返回 000，无代理），
> 故本表基于既有认知而非当场核对，标注为「待验证」的项需你 clone 后复核。

| 项目 | 定位 | 与本项目的可比性 | 可信度 |
|---|---|---|---|
| Termux | Android 上的 Linux 环境 | **是环境不是 App**。用户需自行 apt install node，再跑 CLI | 高 |
| Claude Code 移动端 / Cursor 移动端 | 官方 | **全部是远端桥接** —— 印证远端路线是主流共识 | 高 |
| Aider / OpenHands | 桌面/服务端 | 无原生手机版 | 高 |
| 「AI 编程」类 App（多数） | 套壳对话 | 几百行，无文件/命令工具，价值低 | 中 |
| Continue / Cline 移动移植 | 未见成熟方案 | 待验证 | 低 |

**结论**：「完整的本地编程 agent」在 Android 上**没有成熟先例**。
这不是我们做得晚，而是**手机上做这件事有真实的物理限制**（见下节）。

## 二、手机上做本地 agent 的真实限制（决定设计边界）

这些限制**不是工程问题，是平台约束**，必须写进设计前提：

| 限制 | 影响 | 应对 |
|---|---|---|
| **无 shell** | Android 沙箱不提供 `/bin/sh`；`Runtime.exec` 只能调系统二进制 | 本地模式的「执行命令」工具**无法实现**，改用「伪工具」或明示需 Termux |
| **无任意文件系统访问** | targetSdk 30+ 只能用 SAF / App 私有目录 | 工作区限定为用户授权的目录（SAF） |
| **后台易被杀** | 长时间 agent 循环会被系统回收 | 用前台服务（Foreground Service）+ 通知常驻 |
| **电量与发热** | 长上下文推理会显著耗电 | 限制单轮长度、支持流式增量、避免轮询 |
| **无 Node** | 不能复用任何 Node 生态（109 个依赖全部不可用） | 全部改用 Kotlin 实现 |

## 三、目标架构

```
┌─────────────────────────────────────────────┐
│            Android App（同一个 APK）          │
│                                             │
│  ┌─────────────┐        ┌─────────────────┐ │
│  │  远端模式    │        │   本地模式       │ │
│  │ （已有）     │        │  （新增）        │ │
│  ├─────────────┤        ├─────────────────┤ │
│  │ WebSocket   │        │ 直连 Provider   │ │
│  │ → CLI 桥接  │        │ (API key)      │ │
│  │ 工具在电脑跑 │        │ 工具在手机跑     │ │
│  └─────────────┘        └─────────────────┘ │
│         │                       │           │
│         └───────┬───────────────┘           │
│                 ▼                           │
│        ┌──────────────────┐                 │
│        │  共享层（复用）    │                 │
│        │ · 消息模型/渲染    │                 │
│        │ · 偏好设置体系     │                 │
│        │ · 工具气泡/折叠    │                 │
│        │ · 语音/通知/搜索   │                 │
│        └──────────────────┘                 │
└─────────────────────────────────────────────┘
```

**关键设计决策**：两种模式**共享 UI 与偏好层，只替换「代理后端」**。

- 远端模式的后端 = 现有 `BridgeClient`（WebSocket）
- 本地模式的后端 = 新增 `LocalAgentClient`（直连 Provider HTTP）

这样共享了已完成的全部 UI 工作（工具气泡、回合分组、折叠、语音、
搜索、未读提示…），本地模式只补「推理循环 + 工具执行 + API 配置」。

## 四、分阶段实施计划

### 阶段 1：模式切换骨架（无推理能力，可验证）
- [ ] `AppMode` 枚举（REMOTE / LOCAL），持久化到 `ScanPortPrefs` 同级的存储
- [ ] 设置页加模式切换；切到本地时隐藏「连接/会话扫描」相关 UI
- [ ] `AgentBackend` 接口：`send(text)`, `events: Flow<Event>`, `stop()`
- [ ] `BridgeClient` 适配为该接口的实现（**纯接口抽取，不改行为**）
- **验证**：两种模式都能收发（本地模式先送 echo 桩）

### 阶段 2：API 层与配置（本地模式的核心）
- [ ] `ProviderConfig`：baseURL / apiKey / model / headers / 超时
  - 参考本仓 `src/services/api/openaiCompat.ts` 的配置形态
- [ ] 多 provider 预设（OpenAI 兼容 / Anthropic / DeepSeek / 通义 …）
- [ ] API key 存储：**不落明文**，用 EncryptedSharedPreferences
- [ ] 设置页：provider 选择、key 输入、模型名、连接测试（发一条 ping）
- **验证**：能真实调通一个 provider，收到一次回复

### 阶段 3：推理循环 + 工具协议
- [ ] 精简 agent 循环（单轮：组装消息 → 调 API → 解析 tool_calls → 执行 → 回填）
- [ ] 工具集（手机能做的）：
  - `read_file` / `write_file` / `list_dir` / `search_in_files`
  - **不做 `run_command`**（沙箱禁止）—— 改为明示「本地模式不支持执行命令」
- [ ] 工作区：SAF 目录授权 + 越界防护（路径必须落在授权根内）
- [ ] 工具调用渲染复用现有工具气泡（`ChatMessage.tool` 已就位）
- **验证**：让它在授权目录里读一个文件并回答相关问题

### 阶段 4：健壮性（手机特有）
- [ ] 前台服务：长任务不被杀，通知显示进度
- [ ] 中断：用户可随时停止（已有 `sendInterrupt` 的实现可参考）
- [ ] 错误处理：网络失败、key 失效、token 超限、目录权限丢失
- [ ] 上下文管理：超长时自动截断或摘要（手机内存有限）
- **验证**：切后台 5 分钟回来，任务仍在跑

### 阶段 5：配置项全量（你明确要求）
照搬现有偏好体系（`LocalPrefs` + `ScanPortPrefs` 模式）并扩展：

| 分类 | 项 |
|---|---|
| 外观 | 主题 / 字号 / 密度 / 时间格式（已有） |
| 消息 | 流式 / 自动滚动 / Markdown / 代码着色（已有） |
| 通知 | 回复 / 需介入 / 抑制 / 声音 / 语音播报（已有） |
| **本地模式** | provider / model / 温度 / 最大 token / 系统提示词 / 工作区目录 / 最大轮数 / 工具开关 |
| 安全 | key 存储方式 / 危险操作确认 / 工作区越界策略 |

**设计原则**：每项都要有 `默认值 + 说明文字`（照现有 `Definition` 模式），
且默认值 = 当前行为，避免升级后界面突变。

## 五、不做什么（明确排除，避免范围蔓延）

| 不做 | 原因 |
|---|---|
| 把 doge-code 移植到手机 | 77 万行 + 9 个 Node API 依赖，实测不可行 |
| 本地模式支持执行 shell | Android 沙箱不提供，硬做只能靠 Termux |
| 完整复刻 100+ CLI 命令 | 绝大多数依赖电脑环境（git、npm、编译器等） |
| 抄任何竞品代码 | 无网络获取；且现有竞品均是不同定位 |
