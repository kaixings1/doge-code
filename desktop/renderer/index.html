请求加工管线

客户端请求在转发上游前会依次经过这些加工步骤。这里可以看到每一步实际改了什么，并临时启停某个步骤。

正在加载管线状态…

开关是运行时的，重启后会回到启动时的组合。要永久关闭某个步骤，用启动环境变量 WORKBUDDY_PIPELINE_DISABLE=strip-meta,sanitize-identity。
字节增量显示该步骤让请求体变大或变小了多少：strip-meta 为负（删掉了元数据头）， sanitize-identity 为正（改写了身份描述并注入真实模型名）。 含图片的请求会整条跳过管线，避免破坏 base64。

步骤说明

desensitize 敏感词插零宽空格，规避上游内容审核误拦（词表见「脱敏」页）。
ensure-system 首条消息不是 system 时补一条兜底系统提示。
strip-meta 删除被误塞进 system 的 x-anthropic-* 内部元数据整行。
sanitize-identity 把「我是 Claude Code 官方 CLI」这类自我介绍改写为中性描述。 这是规避上游 11128（unapproved channel）的关键一步，只改 system，不碰对话内容。
