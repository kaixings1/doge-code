# 项目说明
## 核心问题解答
### 1. 依赖会不会造成程序不稳定或内存垃圾无法回收？
依赖是否影响稳定性和内存回收取决于依赖的质量和使用方式：
- **不稳定风险**：若依赖为Alpha/Beta版本、维护不活跃或本身存在内存泄漏/边界场景处理缺陷，确实可能导致程序崩溃、卡死。建议优先选择成熟稳定、社区活跃的依赖，定期更新依赖以修复已知问题。
- **内存垃圾回收问题**：部分依赖若未正确释放资源（如未关闭文件流、未解除事件监听、缓存无上限），会导致内存泄漏，垃圾回收器无法回收无用内存。可通过内存分析工具（如Node.js的`heapdump`、Chrome DevTools内存面板）定位泄漏点。
---
### 2. 如何实现长时间运行、设定目录批量处理并最终输出结果？
针对长时间运行场景，本项目提供以下解决方案：
- **断点续传机制**：处理过程会定期保存中间结果到指定目录，程序中断后重启会自动跳过已处理内容，无需重新计算。
- **内存优化策略**：单批次处理数据后主动释放内存，避免内存积压；大文件分批读取处理，不会一次性加载全部数据到内存。
- **批量目录配置**：只需配置输入目录路径，程序会自动遍历目录下所有符合规则的文件，处理后统一输出到指定目录，支持后台运行，处理完成后会有日志提示。
- **进程守护**：配合`pm2`等进程管理工具，可实现程序崩溃自动重启、内存超限自动重启，保障长时间运行稳定性。

## 快速开始
\`\`\`bash
# 安装依赖
bun install
# 基础运行
bun run start
# 批量处理目录（详细配置见 USAGE.md）
bun run start --input ./data --output ./result
\`\`\`
## 常见问题
- 程序运行一段时间后卡死：检查是否有内存泄漏，开启内存监控自动重启
- 处理大目录超时：调整单批次处理数量，开启断点续传
