# 需求分析：程序卡死问题调试方法论

## 1. 目标分析

### 核心问题
程序运行过程中出现"卡死"（无响应/死锁/无限循环）现象，无法正常继续执行。

### 调试目标
- 精确定位程序卡死的代码位置
- 分析卡死原因（死锁、资源竞争、无限循环、IO阻塞等）
- 修复问题并验证修复有效性

## 2. 输入/输出分析

### 输入
- 源代码文件（多语言支持：Python/Java/C++/Go/JavaScript等）
- 运行环境配置
- 问题复现步骤

### 输出
- 卡死点定位报告（精确到行号）
- 根因分析文档
- 修复后的代码
- 验证日志（证明修复有效）

## 3. 约束条件

### 技术约束
- 不能使用调试器（如gdb、pdb）直接附加到进程（可能无法复现）
- 必须通过代码插桩（日志）方式定位
- 日志输出不能影响程序原有逻辑（避免副作用）
- 最终必须清理所有调试日志（要求1：全部运行没有问题才可以把之前加的日志全部删除了）

### 环境约束
- 支持多平台（Linux/Windows/macOS）
- 支持多语言项目
- 日志输出必须即时刷新（避免缓冲区延迟导致误判）

## 4. 成功标准

1. **定位成功**：通过增量日志法，精确定位到卡死的具体代码行（误差范围：±5行）
2. **修复有效**：修复后程序能够正常运行，不再卡死
3. **日志清理**：验证修复后，删除所有调试日志，代码恢复整洁
4. **可复现性**：相同输入条件下，程序行为一致（不卡死）

## 5. 调试方法论：增量日志法（Binary Search Logging）

### 核心原理
通过二分查找的思想，在代码中逐步添加日志，缩小卡死点的范围。
