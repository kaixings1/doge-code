技能存在的意义，在于从一个随机系统中驯服出确定性。**可预测性**——即 Agent 每次运行都走同样的_流程_，而非产出同样的输出——是根本的美德；下文中的每一项手段都为它服务。

**加粗术语**在 [`GLOSSARY.md`](GLOSSARY.md) 中有定义；请查阅该文件获取完整含义。

## 调用

两种选择，各自承担不同的成本：

- **模型调用**的技能保留一个 **description**，因此 Agent 可以自主触发它，_并且_ 其他技能也能调用它（你仍然可以手动输入它的名称）。它会产生**上下文负载**——description 每一轮都占据上下文窗口。机制：不设置 `disable-model-invocation`，并编写面向模型的 description，使用丰富的触发措辞（"当用户想要……、提到……时使用"）。
- **用户调用**的技能将 description 从 Agent 的可见范围中移除：只有你输入其名称才能调用它——其他任何技能也无法调用。零上下文负载，但会消耗**认知负载**：_你_ 就是必须记住它存在的索引。机制：设置 `disable-model-invocation: true`；此时 `description` 变为面向人类——一行摘要，触发列表被移除。

只有当 Agent 必须自行触达该技能，或其他技能必须调用它时，才选择模型调用。如果它只会被手动触发，就让它成为用户调用，不支付任何上下文负载。

当用户调用的技能多到超出你能记住的范围时，堆积的认知负载可以由一个**路由技能**来化解：一个用户调用的技能，列出其他技能的名称以及何时使用它们。

## 编写 description

模型调用的 **description** 承担两项工作——说明技能是什么，以及列出应触发它的**分支**。每个词都会增加**上下文负载**，因此 description 比正文更值得进行狠心的裁剪：

- **把技能的引导词放在前面**——description 是它执行调用职责的地方。
- **每个分支一个触发条件。** 给同一个分支改名的同义词就是**重复**——"使用 TDD 构建功能……要求测试优先开发"是同一个分支写了两遍。合并它们；只保留真正不同的分支。
- **删掉正文中已有的身份信息。** description 只保留触发条件，外加任何"当其他技能需要……时"的调用条款。

## 信息层级

技能由两种内容类型构成——**步骤**和**参考**——它们可以自由混合：一个技能可以全是步骤、全是参考，或两者兼有。核心决策是使用哪种类型，以及每个内容位于**信息层级**的哪一级——这个阶梯按 Agent 需要材料的紧迫程度排序：

1. **技能内步骤**——`SKILL.md` 中的有序操作，是主要层级：Agent 要做什么，按什么顺序做。每个步骤以一个**完成标准**结尾，即告知 Agent 工作已完成的条件。让它_可检验_（Agent 能区分完成与未完成吗？），且在重要之处让它_穷尽_（"每个被修改的模型都已覆盖"，而不是"产出一个变更清单"）——模糊的标准会诱发**过早完成**。
2. **技能内参考**——`SKILL.md` 中的定义、规则或事实，按需查阅。往往是一个合理的扁平同侪集合（一次评审的所有规则放在同一级）——这是良好的安排，不是坏味道。_本技能全部是参考。_
3. **外部参考**——被推出 `SKILL.md`、放入单独文件的参考，通过一个**上下文指针**到达，仅在指针触发时加载。（范围从_已披露_的参考——如 `GLOSSARY.md` 这样的同级文件，仍属于本技能——一直到完全的**外部参考**，它存在于技能系统之外，任何技能都可以指向它。）

一个严格的完成标准会推动充分的**深入调查**——Agent 在工作过程中所做的挖掘——无论技能是否有步骤，因为"每条规则都已应用"约束扁平参考，正如"每个步骤都已完成"约束一个序列。

下推太少，顶层就会臃肿；下推太多，就会隐藏 Agent 真正需要的材料。这种张力就是全部的决策。

**渐进披露**就是沿阶梯向下移动的动作——从 `SKILL.md` 移入一个链接文件——让顶层保持清晰可读。机制：技能文件夹中的一个链接的 `.md` 文件，以其内容命名（本技能将其完整定义披露到 `GLOSSARY.md`）。有些技能有多种使用方式，每种不同的方式就是一个**分支**——不同运行在技能中走不同的路径。分支是披露最干净的检验标准：所有分支都需要的内容内联，只有部分分支会触达的内容推到指针之后。**上下文指针**的_措辞_——而非其目标——决定了 Agent 何时以及多可靠地触达材料。

层级决定一段内容位于阶梯的_多深处_，而**共置**决定它到位之后_旁边放什么_：把一个概念的定义、规则和注意事项放在同一个标题下，而非散落各处，这样读到一个部分时它的邻近内容也随之而来。

## 何时拆分

**粒度**是你划分技能的精细程度，而每一次切分都会消耗两种负载之一，所以只在切分物有所值时才拆分。两种切法：

- **按调用拆分**——当你有一个独立的**引导词**应当独自触发它，或其他技能必须调用它时，拆分出一个**模型调用**的技能。你要为新常驻加载的 **description** 支付**上下文负载**，因此这种独立的可触达性必须物有所值。
- **按序列拆分**——当一段**步骤**序列中尚未执行的步骤（某步骤的**完成后步骤**）诱使 Agent 赶完眼前这一步时（**过早完成**），拆分这些步骤。让它们不进入视野，能鼓励 Agent 在当前任务上做更多**深入调查**。

## 裁剪

让每个含义保持**单一事实来源**：一个权威位置，这样改变行为只需在一处编辑。

逐行检查**相关性**：它是否仍与技能的功能相关？

然后逐句搜寻**无效行**，而不仅仅是逐行：对每个句子单独运行无效行测试，当某句不通过时，删除整句，而不是从中删减词语。要果断——大多数不通过的散文应当直接删掉，而不是重写。

## 引导词

**引导词**是一个已经存在于模型预训练中的紧凑概念，Agent 在运行技能时用它来思考（例如 _lesson_、_fog of war_、_tracer bullets_）。它在全文中反复出现（虽非必然——一个强的引导词可能只需出现一次），通过调用模型已有的先验，以最少的 token 积累出分布式的定义，并锚定一整片行为区域。

它从两方面服务可预测性。在正文中，它锚定_执行_：每当该词出现，Agent 都会采用同样的行为。在 description 中，它锚定_调用_：当同一个词出现在你的提示词、文档和代码中时，Agent 会把这种共享语言与技能关联起来，更可靠地触发它。

寻找机会重构技能以使用引导词。在三处展开的一个三元组（**重复**）、用一个句子暗示某个想法的 description——每一处都是恳求**坍缩**为单个 token 的段落。例如：

- "fast, deterministic, low-overhead" -> _tight_ ——在某个阶段反复重申的一种特质——坍缩为一个预训练好的单词（一个 _tight_ 循环）。
- "a loop you believe in" -> _red_ ——把一个模糊的门槛转换为一个二元的可观察状态（循环遇到 bug 变 _red_，或者不变）。

你会赢得两次：更少的 token，_以及_一个更锐利的钩子供 Agent 悬挂它的思考。假定每个技能都带着可以被引导词淘汰的重复表述——去找出它们。

## 失败模式

用这些来诊断用户可能在技能上遇到的问题。

- **过早完成**——在步骤真正完成之前就结束它，注意力滑向_完成的状态_本身。防御手段，按序：先锐化完成标准（廉价、局部）；只有当它不可再模糊_且_你观察到赶工行为时，才通过拆分（序列切分）隐藏完成后步骤。
- **重复**——同一含义出现在多处。增加维护成本和 token 消耗，并把一个含义在层级上的显著性抬高到超过其真实地位。
- **沉积**——因为添加显得安全、删除显得有风险而层层堆积的过时内容。任何没有裁剪纪律的技能的默认命运。
- **蔓延**——技能单纯太长，即使每一行都是鲜活的、独特的。损害可读性和可维护性，浪费 token。疗法就是层级：把**参考**藏到指针之后进行披露，并按**分支**或序列拆分，让每条路径只承载它需要的内容。
- **无效行**——模型默认就会遵守的行，因此你付出负载却什么也没说。检验：它相对于默认行为改变了行为吗？一个弱的引导词（当 Agent 本来就相当彻底时的 _be thorough_）是无效行；解决办法是一个更强的词（_relentless_），而不是换一种技巧。
- **否定**——用禁令来引导会适得其反：_don't think of an elephant_ 点名了大象，让它更显眼而非更隐没。提示**正面**行为——陈述目标行为，让被禁止的行为根本不被提及；只有在你无法用正面措辞表达硬性护栏时才保留禁令，即便如此也要配上应当怎么做。
