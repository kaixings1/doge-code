# 类型提示与强类型

## 通用规则

- **优先强类型**：对所有函数参数和返回值使用类型提示。避免留空类型。
- **最小化 `Any`**：尽可能使用特定类型或 `Generic`。避免使用 `Any`，因为它绕过了类型检查。
- **无双引号类型提示**：当存在 `from __future__ import annotations` 时，使用裸类型名（例如 `list[str]` 而非 `"list[str]"`）。
- **始终包含 `from __future__ import annotations`**：每个源文件必须立即在许可证头之后、任何其他导入之前包含此语句。这支持前向引用类而无需引号（PEP 563）。

## `Optional[X]` vs `X | None`

代码库同时使用两种风格。遵循此约定：

- **新代码**（尤其是在 `workflow/` 中）：优先使用 `X | None` — 更简洁和现代。
- **现有文件**：匹配文件中已使用的风格以保持一致性。
- **两者都可接受** — 没有理由不要将一种重构为另一种。

## 函数参数的抽象类型

使用 `collections.abc` 中的抽象类型作为函数参数注解。这接受最广泛的输入范围同时保持类型安全。对返回注解使用具体类型，为调用者提供最有用的信息。

## 关键字参数

使用 `*` 强制具有多个相同类型参数或参数顺序容易出错的函数使用关键字参数。这是 ADK 中广泛使用的模式（16+ 文件）。

**何时使用 `*`：**
- 具有 2 个以上非 self 参数的构造函数（`__init__`）
- 交换参数会静默产生错误结果的任何函数
- 具有多个 `str` 或 `int` 参数的方法

## 可变默认参数

**绝不使用可变默认参数。** 使用 `None` 作为哨兵值，在函数体中初始化。这是 ADK 中广泛遵循的模式。

这适用于 `list`、`dict`、`set` 和任何其他可变类型。

## 使用 `isinstance()` 进行运行时类型区分

在处理多态输入时使用 `isinstance()` 进行运行时类型区分。这在 ADK 中广泛存在（700+ 处使用）。优先使用带有清晰回退的穷举 `if/elif` 链。

**指南：**
- 始终包含一个引发 `TypeError` 或处理未知情况的 `else` 分支。
- 优先使用 `isinstance(x, SomeType)` 而非 `type(x) is SomeType` — 它能正确处理子类。
- 检查多个类型时：`isinstance(x, (TypeA, TypeB))`。

## 生产代码中不使用 assert

**绝不要在生产代码中使用 `assert` 语句。** Python 以 `-O` 参数运行时它们会被优化掉，且报错信息很差。请改用具体的异常类型，例如 `ValueError`、`TypeError` 或 `RuntimeError`。
