# 向导（Wizard）

**向导** 是一个 bash 脚本，逐步引导用户完成一个手动程序，手动操作既繁琐，每次重新向 AI 解释也繁琐。它打开每个 URL，确切说明点击和复制什么，捕获值，将它们写入它们所属的位置（`.env`、GitHub secrets），在每个阶段确认，并显示还剩多少。它可能配置第三方服务、运行一次性迁移，或将项目从一个状态移动到另一个状态。

令人愉悦的 UX 已经由 [template.sh](template.sh) 解决 — 带剩余时间的进度、确认门、跨平台 URL 打开（包括 WSL）、隐藏密钥输入、幂等的 `.env` upsert、`gh secret`/`gh variable` 写入，以及结束摘要。**你的工作只是定义程序的范围并编写其阶段。** `STAGES` 标记之上的库在每个向导中都是相同的；一致性就是要点 — 永远不要手动编辑它。

向导默认是临时的 — 为一次运行构建，保存到临时或 `scripts/` 路径，工作完成后删除。仅在用户想要一个可重复的设置路径应该留在仓库中时才提交它。

## 流程

### 1. 定义程序范围

搞清楚人类必须采取的每一个手动步骤以及过程中捕获的每一个值。首先阅读仓库 — 不要冷启动询问：

- 对于设置：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置，以及 `.github/workflows/*`（每个 `secrets.*` / `vars.*` 引用都是向导必须产生的值）。
- 对于迁移或转换：当前状态、目标状态、以及它们之间的不可逆操作。

然后向用户展示阶段的排序列表和每个阶段产生的值，并确认 — 他们可以添加、删除或重新排序。

**完成条件：** 每个阶段都按顺序命名，对于每个捕获的值你知道 (a) 人类从哪里获取它，(b) 它被写入哪里（`.env`、GitHub secret、两者，或无处 — 某些阶段是纯操作），和 (c) 它是否保密（隐藏输入）或公开。

### 2. 映射每个阶段的流程

对于每个阶段，编写人类遵循的精确路径：打开哪个 URL、在那里做什么、值在哪里显示、它填充哪个变量 — 例如 "Dashboard → Developers → API keys → Reveal test key → copy"。当你实际上不知道当前 UI 或确切命令时，说出来并询问用户或检查文档 — 永远不要发明可能不存在的步骤。

**完成条件：** 每个阶段都追溯到陌生人可以遵循的具体说明。

### 3. 编写向导

将 `template.sh` 复制到目标路径。用每个步骤的一个 `stage` 替换示例阶段，按依赖顺序排列。使用库辅助函数 — `stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm` — 并将 `TOTAL_STAGES` 和 `TOTAL_MINUTES` 设置为诚实的估计值（这驱动剩余时间显示）。

达到模板设置的标准：在询问值之前打开 URL，对任何保密内容使用 `ask_secret`，对每个持久化值使用 `write_env`，仅对 CI 实际需要的值使用 `set_secret`，在任何不可逆操作之前使用 `confirm`。每个 `stage` 清除屏幕，因此只有当前步骤可见 — 将每个阶段保持在一个聚焦的任务，这样人类需要的任何东西都不会滚动消失。不要触摸标记上方的库。

### 4. 验证和移交

- `bash -n <script>`；如果可用，运行 `shellcheck`。
- `chmod +x <script>`。
- 不要自己端到端运行它 — 它打开浏览器并阻塞人工输入。改为静态追踪它：第 1 步中的每个值都被捕获并落在第 1 步所说的位置，每个 `set_secret` 名称与 CI 中的 `secrets.*` 引用完全匹配。
- 告诉用户如何运行它。如果它是可重复的设置路径，提交它并从 README 链接它，这样下一个人运行脚本而不是询问 AI。
