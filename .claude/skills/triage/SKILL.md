# 问题分类

通过小型状态机将项目问题跟踪器上的问题进行分类。

如果此仓库将外部拉取请求视为请求表面（参见问题跟踪器配置），则分类也涵盖它们：**PR是附带代码的问题** — 相同的角色、相同的状态、相同的机器，下面有一些标记为"对于PR"的差异。根据跟踪器配置将裸`#42`解析为问题或PR。

在分类期间发布到问题跟踪器的每个评论或问题**必须**以以下免责声明开头：

```
> *此内容由AI在分类过程中生成。*
```

## 参考文档

- [AGENT-BRIEF.md](AGENT-BRIEF.md) — 如何编写持久的代理简报
- [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md) — `.out-of-scope/`知识库的工作原理

## 角色

两个**类别**角色：

- `bug` — 某些功能已损坏
- `enhancement` — 新功能或改进

五个**状态**角色：

- `needs-triage` — 维护者需要评估
- `needs-info` — 等待报告者提供更多信息
- `ready-for-agent` — 完全指定，准备由AFK代理处理
- `ready-for-human` — 需要人工实现
- `wontfix` — 不会采取行动

对于PR，相同的状态针对附加的代码：`ready-for-agent`表示已附加简报，代理应在差异上采取下一步；`ready-for-human`表示已准备好由人工合并。

每个分类的问题应恰好携带一个类别角色和一个状态角色。如果状态角色冲突，请标记并询问维护者后再执行任何操作。

这些是规范的角色名称 — 问题跟踪器中使用的实际标签字符串可能不同。映射应该已提供给您 - 如果没有，请运行`/设置-matt-pocock-skills`。

状态转换：未标记的问题通常首先转到`needs-triage`；从那里移动到`needs-info`、`ready-for-agent`、`ready-for-human`或`wontfix`。`needs-info`在报告者回复后返回到`needs-triage`。维护者可以随时覆盖 — 标记看起来不寻常的转换并在继续之前询问。

## 调用

维护者调用`/triage`并用自然语言描述他们想要什么。解释请求并采取行动。示例：

- "显示任何需要我注意的内容"
- "让我们看看#42"（问题或PR）
- "将#42移动到ready-for-agent"
- "哪些内容已准备好供代理处理？"

## 显示需要注意的内容

查询问题跟踪器并按最旧优先呈现三个桶：

1. **未标记** — 从未分类。
2. **`needs-triage`** — 评估进行中。
3. **`needs-info`，自上次分类注释以来有报告者活动** — 需要重新评估。

当PR在范围内时，在这些桶中包含外部PR，并将每行标记为`[PR]`或`[issue]`。发现仅显示*外部*PR（跟踪器配置定义谁算作外部） — 协作者正在进行的PR不是分类工作。此过滤器仅用于发现；明确命名的PR始终进行分类，无论作者是谁。

显示计数和每个项目的一行摘要。让维护者选择。

## 分类特定问题或PR

1. **收集上下文。** 阅读完整的问题或PR（正文、评论、标签、作者、日期；对于PR，还包括差异）。解析任何先前的分类注释，以免重新询问已解决的问题。使用项目的领域词汇表探索代码库，尊重该区域的ADR。对代码库运行两个检查：(a) **冗余** — 按领域概念（不仅仅是请求的措辞）搜索现有实现，并报告您查看的位置。如果找到，则是一个已实现的`wontfix`（步骤5）。(b) **先前拒绝** — 阅读`.out-of-scope/*.md`并显示任何类似此请求的内容。

2. **推荐。** 告诉维护者您的类别和状态推荐及其理由，以及与请求相关的简要代码库摘要 — 包括是否已实现。等待指示。

3. **验证声明。** 在任何详细询问之前，检查声明是否成立。对于错误，根据报告者的步骤重现它。对于PR，确认差异执行其声称的功能 — 检出它，运行相关测试或命令。报告发生了什么：已确认（带有代码路径）、失败或详细信息不足（强烈的`needs-info`信号）。已确认的验证使代理简报更强大。

4. **详细询问（如果需要）。** 如果请求需要充实，请一起运行`/grilling`和`/domain-modeling`技能 — 一次一个问题地将其塑形，锐化领域术语并在决策落地时内联更新`CONTEXT.md`/ADR。

5. **应用结果：**
   - `ready-for-agent` — 发布代理简报评论（[AGENT-BRIEF.md](AGENT-BRIEF.md)）。
   - `ready-for-human` — 与代理简报相同的结构，但注明为什么不能委托（判断调用、外部访问、设计决策、手动测试）。
   - `needs-info` — 发布分类注释（模板如下）。
   - `wontfix` — 关闭，评论取决于*原因*：
     - **已实现** — 更改已存在于代码库中。指出其位置；**不要**写入`.out-of-scope/`（该知识库用于*被拒绝的*请求，而不是已构建的请求）。
     - **已拒绝（错误）** — 礼貌解释，然后关闭。
     - **已拒绝（增强）** — 写入`.out-of-scope/`，从评论链接到它，然后关闭（[OUT-OF-SCOPE.md](OUT-OF-SCOPE.md)）。
   - `needs-triage` — 应用角色。如果有部分进展，可选添加评论。

## 快速状态覆盖

如果维护者说"将#42移动到ready-for-agent"，请信任他们并直接应用角色。确认您将要执行的操作（角色更改、评论、关闭），然后行动。跳过详细询问。如果在没有详细询问的情况下移动到`ready-for-agent`，询问他们是否要编写代理简报。

## Needs-info模板

```markdown
## 分类注释

**我们已确定的内容：**

- 要点1
- 要点2

**我们仍需要您（@报告者）提供的内容：**

- 问题1
- 问题2
```

在详细询问期间解决的所有内容都捕获在"已确定的内容"下，以免工作丢失。问题必须具体且可操作，而不是"请提供更多信息"。

## 恢复先前会话

如果问题或PR上存在先前的分类注释，请阅读它们，检查报告者是否已回答任何未解决的问题，并在继续之前呈现更新后的情况。不要重新询问已解决的问题。
