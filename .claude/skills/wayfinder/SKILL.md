一个松散的想法已经到来——太大以至于一个代理会话无法容纳，并且被迷雾包裹：从这里到计划的路线还没有可见。此技能在仓库的 issue 跟踪器上将其绘制为一个**共享地图**，然后逐个处理其票证。地图是领域无关的——工程工作、课程内容、任何适合此形状的工作。

## 通过名称引用

每张地图和票证都是一个 issue，因此它有一个**名称**——它的标题。在人读到的所有内容中——旁白、地图的决策记录——都通过该名称引用它，永远不要使用裸 id、数字或 slug。一面 `#42, #43, #44` 的墙难以阅读；名称一目了然。id 和 URL 不会消失——名称包裹其链接——但它们*内部*承载，而不是代替它。

## 地图

地图是此仓库 issue 跟踪器上的单个 issue，标记为 `wayfinder:map`——标准产物。其票证是地图的子 issue。

地图是一个**索引**，不是存储。它列出了做出的决策并指向保存其详情的票证；一个决策只存在于一个地方——它的票证——因此地图从不重述它，只概述它并链接。

**地图、其子票证、阻塞和前沿查询物理上在哪里存在取决于跟踪器。** 查阅 `docs/agents/issue-tracker.md`（"Wayfinding operations" 部分）了解*此*仓库如何表达它们。如果该文档不存在，默认为本地 markdown 跟踪器。

### 地图正文

整个地图的低分辨率视图，每个会话加载一次。打开的票证**不会**列出——它们是打开的子 issue，通过查询找到。

```markdown
## Notes

<领域；每个会话应咨询的技能；此工作的常设偏好>

## 决策记录

<!-- 索引——每个已关闭票证一行：足以判断相关性，然后放大链接以查看票证保存的详细信息 -->

- [<已关闭票证标题>](link) —— <答案的一行摘要>

## 迷雾

<!-- 参见 "战争迷雾" 了解什么属于这里 -->
```

### 票证

每张票证是地图的**子 issue**；跟踪器的 issue id 就是它的身份。其正文是问题，大小适合一个 100K token 代理会话：

```markdown
## Question

<此票证解决的决策或调查>
```

两个标签家族：

- `wayfinder:<type>` —— `research`、`prototype`、`grilling`、`task` 之一（参见 [票证类型](#ticket-types)）。
- `wayfinder:claimed` —— 一个会话在任何工作之前**首先**设置这个，这样并发会话会跳过它。

阻塞使用跟踪器的原生语义。票证在每一个阻塞它的票证关闭时是**未阻塞的**。**前沿**是打开的、未阻塞的、未认领的子级——已知的边缘。

答案不是正文的一部分——它在解决时被记录（参见 [通过地图工作](#work-through-the-map)）。解决票证时创建的资产从 issue 链接，而不是粘贴进去。

## 票证类型

- **研究**：阅读文档、第三方 API 或本地资源（如知识库）。创建 markdown 摘要作为链接资产。当需要当前工作目录之外的知识时使用。
- **原型**：通过制作廉价、粗糙、具体的工具有效地提高讨论的保真度——一个大纲、一个粗略的初稿、一个存根，或通过 /prototype 技能的 UI/逻辑代码。将原型作为资产链接。当"它应该长什么样"或"它应该如何表现"是关键问题时使用。
- **提问**：与代理的对话。使用 /grilling 和 /domain-modeling 技能。一次问一个问题。默认情况。
- **任务**：必须在讨论继续之前完成的字面手动工作——没有什么可决定、原型化或研究的。移动数据、注册服务、配置访问。代理在可以时自动化它；否则给人类一个精确的清单。工作完成时解决；答案记录做了什么以及任何结果事实（凭据位置、新 URL、行计数），后续票证依赖这些事实。

## 战争迷雾

地图是**刻意不完整的**：不要绘制你还没能看到的东西。票证之外是迷雾——你能判断正在到来但还不能精确确定的决策和调查的模糊视图，因为它们悬而未决。解决一张票证会清除它前面的迷雾，将现在可指定的任何内容升级为新的票证——一次一张，直到通往目标的路径清晰且没有票证为止。

地图的**迷雾**部分是这个模糊视图被写下来的地方：可疑的问题、以后要重访的领域、你推迟的风险。写得尽可能松散或完整；它同时作为协作者阅读工作走向的指路牌。

**迷雾还是票证？** 测试是你现在能否精确地表述问题——而不是你现在能否回答它。

- **票证时**问题已经很清晰——即使它被阻塞并且你无法对它的操作。
- **迷雾时**你不能那么精确地表述它。不要将迷雾预先切成票证大小的碎片：它比票证更粗糙，一个补丁可能升级为几张票证，或没有，一旦前沿到达它。

迷雾仅排除已经决定的东西（那是决策记录）和已经是票证的东西。

## 调用

两种模式。无论哪种方式，**每次会话永远不要解决超过一张票证。**

### 绘制地图

用户带有松散的想法调用。

1. 运行 `/grilling` 和 `/domain-modeling` 会话以浮出开放的决策。
2. **创建地图**（标签 `wayfinder:map`）：笔记填写完毕，决策记录为空，迷雾已概述。
3. **创建你现在可以指定的票证**作为地图的子 issue——然后在**第二遍**中连接阻塞边（issue 需要 id 才能相互引用）。连接将它们排序到前沿和阻塞中；你无法指定的所有内容留在迷雾中。
4. 停止——绘制地图是一个会话的工作；不要同时解决票证。

### 通过地图工作

用户带有一张地图（URL 或编号）来调用。票证是**可选的**——没有票证，你选择下一个决策，而不是用户。

1. 加载**地图**——低分辨率视图，不是每个票证正文。
2. 选择票证。如果用户指定了一张，使用它。否则按顺序取第一张前沿票证。**认领它**：在任何工作之前设置 `wayfinder:claimed` 并保存。
3. 解决它——**需要时放大**：按需获取任何相关或已关闭票证的全部正文；调用 `## Notes` 块命名的技能。如果有疑问，使用 `/grilling` 和 `/domain-modeling`。
4. 记录解决方案：将答案作为**解决方案评论**发布，**关闭** issue，并将**上下文指针**附加到地图的决策记录。
5. 添加新浮出的票证（创建然后连接）；将答案使其可指定的任何迷雾升级，从迷雾中清除每个升级的补丁，使其只作为新票证存在。如果决策使地图的其他部分无效，更新或删除那些票证。

用户可以并行运行未阻塞的票证，因此期望其他会话同时编辑跟踪器。
