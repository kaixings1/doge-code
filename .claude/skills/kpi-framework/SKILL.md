# KPI 框架

## 目的

设计一个使团队保持一致并驱动正确行为的指标层次结构。

## 框架

### 北极星指标

- 捕捉交付给客户核心价值的单一指标
- 驱动北极星指标的输入指标（2-5 个杠杆）
- 示例：Spotify = "听歌时间"、 Airbnb = "预订晚数"、 Dropbox = "添加文件数"

### AARRR（海盗指标）

| 阶段 | 指标 | 说明 |
|---|---|---|
| 获取（Acquisition） | 新增用户数、访问量、注册转化率 | 用户如何发现产品 |
| 激活（Activation） | 注册完成率、首次核心行为完成率 | 首次体验是否良好 |
| 留存（Retention） | 次日/7日/30日留存率、DAU/MAU | 用户是否持续回来 |
| 收入（Revenue） | ARPU、LTV、付费转化率 | 商业化能力 |
| 传播（Referral） | NPS、K因子、邀请率 | 用户是否推荐给他人 |

### HEART 框架

| 维度 | 指标 | 测量方式 |
|---|---|---|
| 愉悦度（Happiness） | NPS、CSAT、应用商店评分 | 问卷调查 |
| 参与度（Engagement） | DAU/MAU、使用频率、停留时长 | 产品分析 |
| 采用率（Adoption） | 功能使用率、新用户转化率 | 事件追踪 |
| 留存率（Retention） | 周/月留存、流失率 |  cohorts 分析 |
| 任务成功率（Task Success） | 成功率、错误率、完成时间 | A/B 测试、可用性测试 |

### 领先指标与滞后指标

- **领先指标**：预测未来趋势（如注册用户数、功能使用率）
- **滞后指标**：反映历史结果（如营收、利润）
- 健康体系 = 领先指标主导 + 滞后指标验证

### 输入指标（Input Metrics）

驱动北极星指标的关键杠杆：

| 输入指标 | 驱动北极星 | 责任团队 |
|---|---|---|
| 日均新发布房源 | 预订晚数 | 增长团队 |
| 搜索可用率 | 搜索结果点击率 | 搜索团队 |
| 支付成功率 | 预订完成率 | 支付团队 |

## 使用方式

### 1. 定义北极星指标

```
问题：我们产品的核心价值是什么？
→ Spotify：让用户听到想听的音乐
  → 北极星 = 听歌时间

问题：用户为什么回来？
  → 输入指标：歌单创建数、关注人数、推荐准确率
```

### 2. 建立指标体系

```
北极星指标
    ├── 输入指标（2-5个）
    ├── 领先指标（预测信号）
    ├── 滞后指标（结果验证）
    ├── AARRR 全链路指标
    └── HEART 体验维度指标
```

### 3. 设定目标和阈值

```
目标值 → 警戒线 → 行动阈值
例如：
  次日留存：目标 60% → 警戒 55% → 行动 < 50%
```

## 示例

### 电商产品

```
北极星：月度总交易额（GMV）
  ├── 输入指标：
  │   ├── 日均活跃买家数
  │   ├── 人均下单数
  │   └── 客单价
  ├── AARRR：
  │   ├── 拉新获客成本（CAC）
  │   ├── 注册转化率
  │   ├── 30日留存
  │   ├── 付费转化率
  │   └── 推荐指数 NPS
  └── HEART：
      ├── 搜索成功率
      ├── 购物车放弃率
      ├── 页面加载时间
      └── 投诉率
```

### SaaS 产品

```
北极星：月度经常性收入（MRR）
  ├── 输入指标：
  │   ├── 新增订阅数
  │   ├── 升级/降级率
  │   └── NRR（净收入留存）
  ├── AARRR：
  │   ├── 免费试用注册量
  │   ├── 试用→付费转化
  │   ├── 付费用户留存
  │   └── 客户推荐数
  └── HEART：
      ├── 功能采用率
      ├── 平均使用时长
      ├── 支持工单数
      └── 客户满意度
```

## 实施步骤

1. **定义北极星指标**
   - 与 stakeholders 对齐
   - 确保可测量、可追踪
2. **识别输入指标**
   - 分析历史数据或用户旅程
   - 找到 2-5 个可驱动北极星的关键杠杆
3. **构建仪表板**
   - 使用 BI 工具（Metabase、 Grafana、自建）
   - 实时展示北极星 + 输入指标
4. **建立报告节奏**
   - 每日/每周/每月同步
   - 粉红色：异常时触发讨论
5. **持续优化**
   - 定期评审指标有效性
   - 淘汰不再相关的指标，补充新指标

## 常见陷阱

- 僵尸指标：好看但无法驱动行动，换成可干预指标
- 指标过多：聚焦 5-7 个，避免分析瘫痪
- 虚荣指标：下载量 ≠ 活跃用户，关注行为质量
- 缺乏基线：没有历史数据难以判断好坏
- 部门各自为政：指标需跨团队对齐，避免局部最优

## 限制

- 数字本身不表达因果关系
- 需要结合实际用户研究
- 随产品演进，指标需要定期更新
