# 需求分析文档

## 1. 目标分析
**核心目标**：全面检查项目中的工具、命令及源代码能力，识别清单中未更新的内容。

## 2. 输入/输出分析

### 输入
- 现有工具清单（tools manifest）
- 源代码目录结构
- 配置文件（package.json, requirements.txt等）
- 命令行接口定义
- API文档

### 输出
- 差异报告（清单 vs 实际能力）
- 缺失项清单
- 更新建议
- 验证脚本

## 3. 约束条件
- 必须覆盖所有源代码文件
- 必须识别CLI命令、API端点、工具函数
- 必须对比清单与实际实现
- 需要可重复执行的检查流程

## 4. 成功标准
1. 完成对所有源代码文件的扫描
2. 识别出清单中缺失的所有能力
3. 生成结构化的差异报告
4. 提供可执行的更新建议

## 5. 执行策略
1. 扫描源代码提取所有导出能力
2. 解析清单文件获取已记录能力
3. 对比两者找出差异
4. 生成报告和更新脚本
